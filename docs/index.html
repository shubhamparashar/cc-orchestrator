what it does

A dashboard, then a remote.

It starts as a read-only view of what is happening. Then it lets you act on it, using the same Claude CLI you already run, with permissions left on.

Live board F1

Title, repo and branch, entrypoint (terminal, VS Code, Desktop), status, context-window percentage, last user and assistant message, PR links. Refreshes over SSE the moment a transcript is written.

Attach in Terminal F2

Opens a terminal running claude --resume <id> in that session's own working directory. No copying UUIDs by hand.

Send or fork a prompt F2

Headless claude -p --resume, default permission mode, never --dangerously-skip-permissions. Fork instead when you want a branch of the conversation rather than a continuation.

Cost and health

Per-session token spend and health, so the runaway 900k-token session is visible before the bill is.

Remote control shim

An opt-in ~/.zshrc alias that adds --remote-control to every interactive launch, so sessions are steerable from claude.ai too. Reversible: delete the marked block.

Phone access

A Tailscale link and a one-tap tokenized URL. The board in your pocket, on your own tailnet, not on the public internet.

running

Process alive and the transcript was written within the last 90 seconds.

waiting-on-input

Process alive, Claude's turn is finished. This is the column that costs you wall-clock time.

open-idle

Process alive, no recent turn.

idle / archived

No live process, or archived in Claude Desktop.

phase 2

Sessions that remember where they left off.

A session ends and its context evaporates. cc-orchestrator keeps a rolling, capped summary per session and an index across all of them, so the next session starts from what the last one knew.

Rolling context files F3

One ~/.claude/contexts/<uuid>.md per session: goal, key files, decisions, state, next step. Around 50 lines, merged and shrunk on every update, never appended to. Written by a detached Haiku job, so nothing runs on the hot path.

Retrieval that costs nothing F4

A pure lexical ranker over the context index: weighted title and tags, then goal, repo and body, with recency and same-repo boosts. Sub-millisecond, no model call, so surfacing related prior sessions on your first prompt is free.

trust model

It reads your sessions. Here is exactly what that means.

0npm dependencies
1file it writes outside its own config: settings.json, on request
0bytes sent anywhere; loopback by default
0600rotating logs under ~/.config

~/.claude and the Claude Desktop storage are opened read-only and never written. Transcripts stay on disk and are never copied. The one exception is cc-install-hooks, an additive merge into ~/.claude/settings.json that backs the file up first and reverses cleanly. Loopback is unauthenticated by design; LAN is plaintext, so use Tailscale for anything off the machine. Full detail in SECURITY.md.

install

Node, one file, no build step.

# fastest
npx github:shubhamparashar/cc-orchestrator        # -> http://127.0.0.1:7433

# from a clone
git clone https://github.com/shubhamparashar/cc-orchestrator
cd cc-orchestrator && node server.mjs

# always-on
brew install --build-from-source ./Formula/cc-orchestrator.rb
brew services start cc-orchestrator
# or ./install-launchagent.sh (macOS) / ./install-systemd-user.sh (Linux)

# double-clickable Mac app, no Electron
./scripts/build-app.sh --dmg

macOS is the primary platform; Linux runs the core dashboard, with a short poll standing in for recursive fs.watch. CI runs the suite and a smoke boot on both.
